# HamNoSys Handshapes

This directory reconstructs the official **HamNoSys 4 Handshapes Chart**
([HamNoSys_Handshapes.pdf](https://www.sign-lang.uni-hamburg.de/dgs-korpus/files/inhalt_pdf/HamNoSys_Handshapes.pdf),
Thomas Hanke, 2010-06-10, drawings by Heiko Zienert, Olga Jeziorski, Andreas Hanß —
University of Hamburg, DGS-Korpus project).

> Please note that this chart aims at demonstrating how HamNoSys handshape notations are constructed,
> by no means is this chart an exhaustive list of HamNoSys handshape notations.

Every hand drawing from the PDF is extracted into [`images/`](images/), named after the
hexadecimal Unicode codepoints of its HamNoSys notation (e.g. `e002-e00d.png` is
`hamfinger2 hamthumbacrossmod`). [`handshapes.json`](handshapes.json) lists every chart cell with its
section, row (handshape class), column, HamNoSys string, symbol names, and image file.
Cells marked `cf.` are cross-references in the original chart — the notation is equivalent to
another handshape and has no drawing of its own.

## Mapping to SignWriting

The two systems approach handshapes differently: **SignWriting works with a closed vocabulary** —
exactly 261 base hand symbols (`S100`–`S204`) in ISWA 2010, each drawn as its own glyph — while
**HamNoSys is an open vocabulary** that *constructs* handshapes from a small set of primitives:
a base form (fist, flat hand, finger2, …), thumb position, bending, and finger-selection modifiers.
The same physical shape can therefore be spelled several ways in HamNoSys, and HamNoSys can express
shapes that have no SignWriting symbol. This is why the mapping below is one SignWriting base to
*many* HamNoSys spellings, and why it can never be complete in the other direction.

[`map.py`](map.py) maps between SignWriting hand symbols and HamNoSys notations:

- **Handshape**: each of the 261 SignWriting hand bases (`S100`–`S204`) maps to a *list* of
  equivalent HamNoSys spellings in [`mappings.json`](mappings.json) — real corpora spell the same
  shape several ways (e.g. the X-hand appears as both `hamfist hamindexfinger hamfingerhookmod` and
  `hamfinger2 hamfingerhookmod`). The first entry is the canonical spelling used by
  `sw_to_hamnosys`; `hamnosys_to_sw` matches any entry. `map.handshapes()` tokenizes a full
  HamNoSys transcription into its handshape tokens.
  [`base_names.json`](base_names.json) carries the official ISWA 2010 base names
  (from [signbank.org/iswa](https://www.signbank.org/iswa/)).
- **Orientation**: a SignWriting symbol key `SXXXFR` encodes fill `F = (symbol - base) / 16`
  (palm facing × wall/floor plane) and rotation `R = (symbol - base) % 16` (finger direction,
  right/left hand). `orientation(fill, rotation)` converts these to HamNoSys extended finger
  direction + palm orientation symbols, so `sw_to_hamnosys("S10012")` returns handshape and
  orientation. The palm convention (unfilled = palm toward the signer in the wall plane, palm up
  in the floor plane; HamNoSys palm symbols are relative to the finger direction) is a first
  approximation for annotators to refine.

`mappings.json` is a work in progress, curated three ways (the rest still need annotation):

1. Best guesses from comparing the hand photos against the HamNoSys chart drawings.
2. Evidence mined from the parallel corpus ([`../parallel.json`](../parallel.json)): for signs
   transcribed in both systems that use exactly one handshape on each side, the co-occurrence
   counts give high-confidence pairs (e.g. `S203` "Fist" ↔ `hamfist hamthumbacrossmod` in 67
   signs). Corpus majorities with ≥4 supporting signs override photo guesses — notably real
   transcriptions write the thumb position explicitly rather than relying on HamNoSys defaults.
3. Human review with the annotation server below.

### Annotation server

Help us complete the mapping:

```bash
pip install ".[server]"
python -m signwriting.hamnosys.handshapes.server  # http://localhost:3030
```

It serves two views over the same `mappings.json` (toggle in the toolbar), and every save writes
straight back to the file — ready to commit:

- **SignWriting → HamNoSys**: all 261 bases with rendered symbol, hand photo (from the
  [Lessons in SignWriting](https://rylo.com/sign/research/lessons-in-signwriting) 3D hands set)
  and their HamNoSys spellings; the editor manages the spelling list per base with a structured
  symbol palette and the chart drawings.
- **HamNoSys → SignWriting**: the inventory of observed HamNoSys handshapes sorted by frequency,
  each with its chart drawing and the SignWriting base it resolves to; the editor assigns a base
  from a picker of all 261 rendered symbols, grouped by ISWA group (hover for the hand photo).

Unmapped rows are highlighted in both directions. External dictionary data (not distributed with
this repository) can enrich the inventory at runtime: point `HAMNOSYS_INDEXES` at CSV files with a
`hamnosys` or `hamnosys_names` column, and/or `PARALLEL_RECORDS` at a jsonl(.gz) of records
carrying HamNoSys transcriptions.

## How a handshape notation is constructed

A HamNoSys handshape is composed of:

1. A **base form** (handshape class): fist, one finger, two fingers (non)spread, flathand, four fingers spread
2. An optional **thumb modifier**: `hamthumboutmod` (out), `hamthumbacrossmod` (across), `hamthumbopenmod` (open)
3. An optional **bending modifier** applied to the selected fingers: `hamflathand`-derived flattening
   (`hamfingerstraightmod`), bending (`hamfingerbendmod`), or hooking (`hamfingerhookmod`)
4. Optional **finger selection** symbols (`hamthumb`, `hamindexfinger`, `hammiddlefinger`, `hamringfinger`,
   `hampinky`) for derivations where specific fingers deviate from the base form
